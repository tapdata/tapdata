本文把详细设计转换为可执行、可跟踪、可逐步验收的开发计划。计划只定义开发顺序、依赖、产出和完成标准，不直接承诺日历排期；负责人、开始日期和完成日期应在任务拆分到 Jira 后补充。

### 1.1 开发范围

本计划包含：

- TM 数据模型、存储、API、批次控制、权限校验、告警、配置和初始化。
- Engine 异常分类、风暴保护、记录捕获、DQL 上报和受控重处理。
- TM 与 Engine 的接口联调、故障注入、一致性验证和 POC 验收。

本计划不包含 Web 路由、菜单、页面、组件、前端 API 封装、i18n 和前端测试。Web 功能由其他人员负责；本计划只负责冻结并交付 Web 所需的 TM API、权限码和错误码契约，接口变化需要同步 Web 负责人。

## 4. 开发原则和关键依赖

1. 先冻结 TM 与 Engine 契约，并向 Web 负责人交付稳定的 API 契约，避免字段、枚举和状态语义反复变更。
2. Engine 捕获链路必须先完成异常分类，再接入 DLQ 上报；不能先把所有错误上报后再补分类。
3. “DLQ 保存成功才允许 skip”是捕获链路的强一致性边界，任何降级都不能破坏该规则。
4. 重处理链路先完成 TM 批次状态机和锁，再开发 Engine 回放，避免出现无审计的直接回放入口。
5. TM 查询 API 只返回 `RECORD_DLQ` 记录；共享异常继续通过任务状态、任务日志和现有任务告警表达。
6. TTL 使用 `ttl_at`，创建时与 `created` 一致，重处理活动时与同次 `updated` 一致；索引只由 iDaaS 初始化脚本创建。
7. POC 的无重复结论只适用于有主键或唯一键、目标支持幂等或 Exactly-Once 的场景。

## 7. 建议的并行开发方式

契约冻结后可按以下工作流并行：

| 工作流 | 可并行范围 | 必须等待的接口点 |
| --- | --- | --- |
| TM 基础 | B01-B12 | A03 字段契约、A05 配置默认值 |
| Engine 捕获 | C01-C12 | B08 上报 API 契约；真实联调等待 M1 |
| TM 重处理 | D01-D10 | A02 状态机、A03 消息与回调契约 |
| Engine 回放 | E01-E10 | D05 消息契约、D06 回调契约；真实联调等待 M3 |
| 告警和初始化 | F01-F07 | 权限、配置和告警口径冻结后可与主链路并行 |

关键路径为：

```text
A03 契约冻结
  -> B08 TM 上报 API
  -> C04-C09 Engine 分类与捕获
  -> G02/G03 捕获联调
  -> D01-D07 TM 批次控制
  -> E01-E09 Engine 回放
  -> G06-G08 重处理与补偿验收
  -> G10-G12 POC 和发布检查
```

Web 由其他人员按独立计划推进。本计划在 A03、B09、B11、D05 和 D09 完成后提供字段、查询、错误码、重处理和批次详情契约，并在契约变化时主动同步。

## 8. 每步统一完成定义

除步骤自身的完成标准外，每个开发步骤还必须满足：

1. 代码与详细设计一致；若实现调整设计，必须先同步相关设计和接口文档。
2. 新增公共字段、枚举、错误码、配置或消息时，TM、Engine 和文档同步更新，并通知 Web 负责人评估接口影响。
3. 正常路径、关键异常路径、幂等和权限边界具备与风险相匹配的自动化测试。
4. 不在外部查询响应、普通日志和告警中输出完整 Payload、密码、Token 或未脱敏错误信息。
5. 不改变未启用 DQL 的任务、现有任务级重试、SkipTable 和 TaskSkipErrorTable 的既有语义。
6. 数据更新涉及状态、`updated`、`ttl_at`、批次 ID 或计数时，应使用原子条件更新并验证修改数量。
7. 新增初始化脚本可重复执行，升级和回滚影响明确。
8. `git diff --check`、模块编译、相关单元测试和契约测试通过。

## 10. 上线前必须明确的决策

以下事项不应由开发人员在实现中自行推断，必须在进入 M6 前明确：

1. POC 权限最终采用单一 View，还是保留独立 Edit 权限；当前代码和详细设计口径需要统一。
2. Storm Guard 触发后使用专用 `TASK_DQL_STORM_GUARD`，还是合并到现有任务错误告警。
3. 同任务互斥锁使用独立 `dql_recovery_locks` 集合，还是使用现有分布式锁能力。
4. 暂停任务 recovery-only runner 支持的任务类型、节点类型和连接器范围。
5. 历史 `dql_events`、`dql_recovery_batches` 是否存在；如存在，是否在上线前将 `created` 回填到 `ttl_at`。
6. DQL 配置是进入 Settings 初始化脚本、部署配置还是任务配置，以及哪些配置支持运行时调整。
7. POC 用于证明无重复的目标连接器、主键/唯一键、写入策略和 Exactly-Once 配置。

以上决策如果未冻结，不影响 Mock 开发，但会阻塞完整联调和最终验收。
