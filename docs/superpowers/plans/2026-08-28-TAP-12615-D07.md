# TAP-12615 D07 实施计划

## 目标

## 设计决策

### 事件结果分类

Repository 的幂等方法统一返回：

| 结果 | Service 行为 |
| --- | --- |
| `APPLIED` | 事件状态/attempt 已原子更新，增加对应批次计数；FAILED 发送一次告警 |
| `DUPLICATE` | 直接成功返回，不写事件，不增加计数，不告警 |
| `CONFLICT` | 同一 attempt 要求不同终态，返回 `DqlRecovery.AttemptConflict` |
| `NOT_IN_BATCH` | 事件不属于当前批次或已不在可更新状态，返回 `DqlRecovery.EventNotInBatch` |

原子更新使用事件当前状态、`current_batch_id` 和同 attempt 不存在作为条件；更新未命中后再读取 attempt 历史用于区分重复和冲突。这样在并发重复回调下，只有一个请求能得到 `APPLIED`。

### 批次结果分类

- RUNNING 批次重复收到 BATCH_STARTED 时不重复执行状态更新。
- SUCCESS/PARTIAL_FAILED 批次重复收到 BATCH_FINISHED 时不重复完成或释放。
- FAILED 批次重复收到 BATCH_FAILED 时不重复释放事件锁、任务锁或重复告警。
- 终态批次中能匹配已保存 attempt 的事件重复回调直接返回；其余回调仍按批次终态拒绝。
