# DQL 从失败节点回放实施计划

> 本计划只覆盖新的“停止任务后从失败节点回放并恢复任务状态”语义，保留工作区中已有 DQL 事件、批次、超时和回调修复。

## 1. 固化接口与数据模型

- 扩展 Engine-facing recovery payload，带回失败节点和任务 DAG 路径所需的节点元数据。
- 增加临时节点状态和 recovery lifecycle 审计契约。
- 保持旧 Payload 数据兼容；缺少失败节点的旧数据明确失败并恢复任务。

## 2. 临时 DAG 裁剪

- 新增纯函数/服务，根据失败节点和目标节点计算保留集合。
- 深拷贝原始 DAG，只在副本中设置 `disabled`。
- 记录隐藏节点的原始状态，恢复时按快照恢复。
- 校验多事件路径一致性，并对无法重建的有状态节点 fail closed。

## 3. Engine 任务生命周期

- 为 `TapdataTaskScheduler` 增加 DQL recovery 专用的同步停止/启动能力。
- 停止正式 Job 后再创建临时回放 Job。
- 回放结束、失败和初始化异常统一走清理及原状态恢复。
- 避免普通任务调度器在回放期间误启动正式任务。

## 4. 临时回放 Job

- 增加可注入任意失败节点输入的 replay source。
- 用原始任务所有节点构建临时 DAG，关闭真实 Source reader。
- 保留失败节点到下游目标的完整处理链和原有事件标记/屏障机制。
- 确保临时 Job 不注册为正式任务，也不覆盖正式任务的运行缓存和状态。

## 5. TM 审计与补偿

- 接收并保存隐藏节点、节点恢复、任务停止/恢复结果。
- 保留现有批次心跳和超时收敛；超时消息包含任务可能仍处于停止状态的提示。
- 对 Engine 回放失败、恢复失败分别记录，确保页面不长期停留在处理中。

## 6. 验证顺序

1. 先新增失败测试并确认失败。
2. 实现 Payload/审计契约。
3. 实现 DAG 裁剪及恢复。
4. 实现 Engine stop/replay/restore 生命周期。
5. 实现临时 replay source 和 Job。
6. 运行 Engine/TM Common/TM 定向测试和模块构建。
7. 执行 `git diff --check`，再进行不触碰业务数据源的集成验证。
