# TAP-12615 D08 实施计划

## 目标

建立 TM 批次超时扫描和补偿机制，收敛回调丢失或 Engine 异常退出造成的 `REPROCESSING` 事件与任务锁，且重复扫描不会重复追加超时 attempt 或告警。

## 设计决策

### 扫描边界

批次仓储只查询 `DISPATCHED`、`RUNNING` 且 `updated` 早于截止时间的批次。`updated` 在批次派发、启动、事件结果计数和状态推进时刷新，能同时覆盖派发阶段卡死和运行阶段无进展。

### 事件补偿

事件仓储使用 `current_batch_id + REPROCESSING` 保护所有权，使用稳定的 `TIMEOUT-{batchId}` attempt 保护扫描重入。一次 `updateMulti` 同时清除事件锁、追加 TIMEOUT 历史、增加恢复次数和刷新 TTL；并发完成回调先命中时，超时更新不会覆盖已完成事件。

### 批次收敛

- 本轮至少有超时事件且没有成功事件：`FAILED`。
- 本轮至少有超时事件且已有成功事件：`PARTIAL_FAILED`。
- 事件仍为 `REPROCESSING` 时不结束批次、不告警、不释放任务锁。
- 终态条件更新成功后再告警和释放锁，避免多个 TM 实例重复执行补偿副作用。
