## P-02 公共类型层次与协议兼容

- 状态：已完成
- 完成内容：在 `tapdata-common-lib` 增加 `TapFloat`、`TapDouble` 及对应值类；二者直接继承 `TapType`，不继承 `TapNumber`；保留 `TYPE_NUMBER=8`，新增 `typeName` 识别；增加 bit、storageBytes、effectivePrecision、binaryPrecision、有限范围和 NaN/Infinity 能力属性，并限制错误的 bit/fixed 设置。
- 兼容结论：旧的数字协议仍按 `TYPE_NUMBER` 恢复 `TapNumber`；新类型通过 `typeName` 区分，旧模型不会因新增类而改变解析路径。
- 验证：先运行失败测试确认新类不存在；实现后 `mvn -q -Dtest=TapFloatingPointTypeTest test` 通过，`git diff --check` 通过。
- 提交：`tapdata-common-lib` `b2f01dc feat(TAP-12568): add TapFloat and TapDouble schema types`

## P-11 数据源 spec 静态质量门禁

- 状态：已完成
- 完成内容：新增独立 Python 检查器和 JSON allowlist；检查两个连接器仓库的 spec 时，强制验证 `TapFloat`/`TapDouble` 的 bit、storageBytes、effectivePrecision，禁止二进制浮点继续携带 decimal precision/scale/fixed 属性，并阻止未登记的浮点候选继续映射到 `TapNumber`。Oracle `FLOAT(p)`、Elasticsearch `half_float`/`scaled_float`、HBase 未解码的字节类型及无法确认的 API 逻辑名称必须带官方链接、理由和 source-file/type 级 allowlist。
- 自审结论：门禁显式把 64 位误标单精度、32 位误标双精度、定点属性残留和未登记候选作为失败项；allowlist 只用于官方定义不是 binary32/binary64 或连接器没有实际二进制承载证据的情况，不能作为默认降级。
- 验证：对现有 MySQL spec 运行检查器，按预期报告 4 个待修复候选；`git diff --check` 通过。
- 提交：`tapdata` `cbffea79d6 feat(TAP-12568): add floating point spec validator`
