# TAP-12568 浮点数适配开发总结

本文档按研发计划表记录每个可验收步骤的实际完成情况。每条记录对应一个本地 Git 提交，提交信息统一使用 `feat(TAP-12568): ...` 格式。

## P-01 基线、契约与计划审核

- 状态：已完成
- 完成内容：完成概要设计、详细设计、研发计划表；确认 `TapFloat`、`TapDouble` 为 `TapType` 的直接子类型，入站值统一以 `Double` 承载；保留 `TapNumber` 作为旧模型兼容类型；确认 74 个数据源 spec 独立修复。
- 审核结论：不设置“第一阶段/第二阶段”尾项，计划覆盖类型、值对象、编解码、推演、序列化、兼容、数据源 spec、验证和产品文档；每个数据源均为独立可验收步骤。
- 验证：计划中的数据源路径全部存在；计划行号、源标识无重复；Markdown fence 成对；文档无未决 TODO/TBD。
- 提交：待提交

## P-02 公共类型层次与协议兼容

- 状态：已完成
- 完成内容：在 `tapdata-common-lib` 增加 `TapFloat`、`TapDouble` 及对应值类；二者直接继承 `TapType`，不继承 `TapNumber`；保留 `TYPE_NUMBER=8`，新增 `typeName` 识别；增加 bit、storageBytes、effectivePrecision、binaryPrecision、有限范围和 NaN/Infinity 能力属性，并限制错误的 bit/fixed 设置。
- 兼容结论：旧的数字协议仍按 `TYPE_NUMBER` 恢复 `TapNumber`；新类型通过 `typeName` 区分，旧模型不会因新增类而改变解析路径。
- 验证：先运行失败测试确认新类不存在；实现后 `mvn -q -Dtest=TapFloatingPointTypeTest test` 通过，`git diff --check` 通过。
- 提交：`tapdata-common-lib` `b2f01dc feat(TAP-12568): add TapFloat and TapDouble schema types`

## P-03 浮点值对象承载与量化

- 状态：已完成
- 完成内容：`TapFloatValue`、`TapDoubleValue` 均以 `Double` 作为平台承载；`TapFloatValue` 在构造器、`value(...)` 和 `setValue(...)` 中统一执行 binary32 量化，避免反射/反序列化路径绕过精度约束；`TapDoubleValue` 保持 binary64 值。
- 验证：先补充构造器、链式 setter、普通 setter 三条入口的失败测试；实现后 `mvn -q -Dtest=TapFloatingPointTypeTest test` 通过，`git diff --check` 通过。
- 提交：`tapdata-common-lib` `184f800 feat(TAP-12568): enforce float value quantization`

## P-04 入站/出站 codec 与默认注册

- 状态：已完成
- 完成内容：新增 `ToTapFloatCodec`、`ToTapDoubleCodec`、`FromTapFloatCodec`、`FromTapDoubleCodec`；入站按目标类型转换，单精度统一 binary32 量化，出站分别返回 `Float`/`Double`；特殊值能力由 schema 的 `supportsNaN`/`supportsInfinity` 控制；旧 `TapNumber` codec 未修改其历史行为；默认 codec 映射增加新值类。
- 验证：先运行缺失 codec 的编译失败测试；实现后浮点入站精度、出站 Java 类型、特殊值拒绝测试通过；`git diff --check` 通过。
- 提交：`tapdata-common-lib` `ecb3e4f feat(TAP-12568): add floating point codecs`

## P-05 Java 类型推导

- 状态：已完成
- 完成内容：`JavaTypesToTapTypes` 改为 `Float -> TapFloat`、`Double -> TapDouble`；移除二者生成 `TapNumber.scale/precision` 的旧推断；`BigDecimal`、整数和其他 `Number` 保持 `TapNumber`；补齐按 `TapFloat.class`/`TapDouble.class` 反向创建类型的分支。
- 验证：先确认旧实现对 Float/Double 的两类测试失败；修改后 `mvn -q -Dtest=JavaTypesToTapTypesTest,TapFloatingPointTypeTest test` 通过，`git diff --check` 通过。
- 提交：`tapdata-common-lib` `7e9829c feat(TAP-12568): infer dedicated Java floating point types`

## P-06 浮点 mapping 与参数化 precision resolver

- 状态：已完成
- 完成内容：新增 `TapFloatMapping`、`TapDoubleMapping` 和 `TapFloatingPointMapping`；静态 mapping 可描述位宽、存储字节、有效精度、二进制 precision、范围和特殊值能力；参数化 mapping 支持 `precision <= 24 -> TapFloat`、`precision >= 25 -> TapDouble`，默认 53；`TapMapping.build` 增加可选 `mapping` 类选择；`TapNumberMapping` 通过兄弟类型隔离，不会匹配新浮点类型。
- 验证：先确认 mapping 类缺失导致测试编译失败；实现后静态 mapping、参数分流、默认双精度和旧 mapping 隔离测试通过；`git diff --check` 通过。
- 提交：`tapdata-common-lib` `2d3cf35 feat(TAP-12568): add floating point mappings`

## P-07 Jackson JSON 类型名与旧协议兼容

- 状态：已完成
- 完成内容：引擎 `JSONUtil`、管理端 `JsonUtil` 的 `TapType` deserializer 均优先读取 `typeName`，再回退到历史 `type=8`；新类型序列化自动输出 `typeName`；旧 numeric-only payload 继续恢复 `TapNumber`，没有新增协议 byte。
- 验证：`iengine-common` 的 `JSONUtilTest` 和 `tm-common` 的 `JsonUtilTest` 均通过，覆盖 `TapFloat`/`TapDouble` 往返及旧 `TapNumber` payload；`git diff --check` 通过。
- 提交：`tapdata` `ad92a69df5 feat(TAP-12568): preserve floating point type names in JSON`
