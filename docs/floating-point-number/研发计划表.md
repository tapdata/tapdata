# 浮点数单/双精度适配研发计划表

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. 计划中的步骤使用状态列跟踪，实施时每个数据源必须独立提交、独立验证。

**Goal:** 按详细设计完成 TapFloat/TapDouble 公共类型、Double 值承载、历史模型兼容、spec 官方定义修复和 TAP-12568 全链路回归。

**Architecture:** 公共 API 保持 TYPE_NUMBER=8，通过 typeName 区分 TapFloat/TapDouble；浮点值对象直接继承 TapValue 并统一使用 Double，单精度入值先做 binary32 量化；参数化 source type 由独立 floating-point mapping resolver 返回具体 TapFloat 或 TapDouble。历史 TapNumber 在模型进入推演、codec 和 DDL 前由 LegacyTapTypeResolver 统一规范化。

**Tech Stack:** Java 8-compatible API、Jackson、Fastjson、现有 TapMapping/DefaultExpressionMatchingMap、Maven、JUnit、连接器 spec.json、官方数据源文档。

**Spec:** /Users/gavinxiao/kit/tapdata/tapdata/docs/floating-point-number/详细设计.md

## Global Constraints

- TapFloat、TapDouble 与 TapNumber 为 TapType 直接业务类型，不增加 TapFloatingPoint 业务类型或新的 TYPE_FLOAT/TYPE_DOUBLE byte。
- TapFloatValue、TapDoubleValue 均以 Double 存储；TapFloatValue 任何入口必须执行 Float -> Double 量化。
- 新发现的实际 binary32/binary64 浮点不得由新 spec 生成 TapNumber。
- 普通浮点不得使用 precision/scale/fixed=true 表达定点约束。
- 历史 type=8 且没有 typeName 的 schema 必须继续恢复 TapNumber。
- 历史模型兼容不得重新访问源端或强制重新加载模型定义。
- 无法唯一恢复历史单双精度时保留 legacy，并对类型敏感操作返回 LEGACY_FLOAT_TYPE_UNRESOLVED。
- 只修改两个连接器仓库的 src/main/resources，不修改 target/classes。
- 每个数据源 spec 修复必须登记官方来源、实际 bit/byte、有效位数、范围、特殊值和参数语义。
- 所有公共 API 变更必须在 Java 8 source/target 配置下可编译。
- 本表的顺序是同一完整交付范围的执行顺序，不代表分阶段交付，也不保留后续尾项。

## 4. 研发验收记录格式

每个公共代码工作包至少记录：

- 修改文件列表。
- 单测命令和结果。
- 兼容性影响。
- 是否改变旧 TapNumber 行为。
- 失败日志和回滚方式。

每个数据源步骤必须单独记录：

- 数据源名称、连接器模块、spec 文件。
- 官方文档 URL 和适用版本。
- 修改前后 dataType key。
- 修改前后 to、bit、storageBytes、effectivePrecision、value、fixed、scale。
- 参数化类型的边界和默认值。
- spec 加载验证结果。
- 端到端验证结果或明确的 allowlist 原因。

建议提交粒度：

- 公共类型/值对象/codec/mapping 按 P-02 至 P-06 分开提交。
- JSON/PDK/历史模型按 P-07 至 P-10 分开提交。
- 每个 S-xx 数据源独立提交，提交信息包含数据源名。
- P-13 只包含最终测试、文档和必要的构建产物更新，不混入新的类型逻辑。

## 5. 计划完成标准

只有同时满足以下条件，计划才可标记完成：

1. P-02 至 P-12 全部完成并有测试证据。
2. S-01 至 S-74 每一行均有独立结果；不能用家族级结果替代。
3. validator 在两个连接器仓库资源根目录上无未解释错误。
4. 实际 binary32/binary64 spec 不再使用 TapNumber。
5. 历史 TapNumber 模型能在无 source metadata reload 的条件下运行。
6. SQL Server float(53) -> StarRocks DOUBLE 回归通过，小数值未被截断。
7. 文档、registry、测试报告和源文件变更清单一致。
